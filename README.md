面向whut有线网的 Windows 10 / 11 x64 工具，用于自动登录账号、保持登录状态。非破解、仅用于学习研究，方便日常使用。

解压后把 `WHUTKeepalive.exe` 放在长期使用的位置，双击即可打开。用户电脑无需另装 Go、Python、WebView2 或其他运行时。初始状态不会注册任务，也没有保存凭据。

## 第一次使用

1. 电脑通过网线接入校园网。打开「网络概览」，点击「立即检测」。检查窗口里的网卡、设备 IPv4 和门户结果；检测失败时可在「网络诊断」查看原因。
2. 在「账号认证」选择有线网卡。建议默认根据 Windows 到门户的路由选卡。默认门户 `http://172.30.21.100`、NAS ID `52`；可自行修改。默认优先使用从同一门户的重定向中识别出的 NAS ID。更改了门户地址时，请先用浏览器核对，并为新地址重新保存凭据。
3. 输入校园网账号和两遍密码，然后保存。程序按原样使用账号（包括用户填写的运营商后缀）；用户名与密码均用当前 Windows 账号的 DPAPI 加密保存。
4. 在「自动保活」修改所需参数，勾选「启用定时检测」，点击「保存并同步任务」。首次启用 HTTP 自动认证时会提示传输风险。请只在地址确认无误后同意；程序验证到 HTTPS 时会优先使用 HTTPS。
5. 首页显示「自动保活：已启用」后即可关闭窗口。若 Windows 拒绝创建任务，设置会保留，但自动保活尚未启用。请在有权创建计划任务的环境中，用**同一个 Windows 用户**重新打开程序并保存。对于有 UAC 提权权限的同一账号，可用「以管理员身份运行」重新注册；任务本身配置为该用户的最低权限。

| 可调参数 | 默认值 | 支持范围 |
| --- | ---: | --- |
| 检测间隔 | 60 秒 | 60–86,400 秒；支持整数秒，例如 91 |
| 连续离线确认 | 2 次 | 1–20 次 |
| 失败冷却 | 300 秒 | 10–86,400 秒 |
| 退避上限 | 3,600 秒 | 不小于失败冷却，最多 604,800 秒 |
| 单次 HTTP 请求超时 | 8 秒 | 1–60 秒 |
| 提交登录后复查等待 | 3 秒 | 0–30 秒 |
| 日志保留 | 14 天 | 1–365 天 |

还可切换 Windows 登录时立即检查、静默执行、失败提醒、旧日志清理及外网探测。Windows 任务计划程序最小重复间隔为 60 秒；休眠期间不唤醒，机器负载和调度策略可能推迟实际触发。

## 软件如何判断和恢复

- 每次计划任务以当前 Windows 用户启动一个检查进程，结束后退出。进程锁和计划任务均避免重叠运行。暂停后旧任务即使未能删除，也不会执行认证。
- 软件用所选有线网卡的 IPv4 直连门户。网线断开、未获得 IP、路由绕开所选网卡、门户超时、未知协议以及门户报告其他设备 IP 都不计作离线。
- 当前设备连续确认未认证后，如没有处在冷却中且凭据可用，才发一次登录请求。收到账号或密码错误后需更新凭据；收到验证码后须在浏览器人工完成。查询到本机已在线时不会重复提交登录。立即登录可跳过离线次数门槛，仍受状态、授权和冷却保护。
- 登录需要门户接受请求，再由在线状态确认选定 IPv4 已上线。若门户已在线但外网探测失败，程序单独显示，不会因此重发账号密码。启用外网探测时，程序从所选网卡向百度首页、腾讯首页发送不含账号或会话的 HTTPS HEAD 请求，可在界面关闭。
- `http://9.9.9.9/` 仅用于读取可能的认证重定向，程序不跟随未知地址，也不向其发送认证信息。软件不修改网卡、DNS 或路由。
- 如果出现「门户报告的 IPv4 与选定网卡不一致」，设备可能位于路由器的 NAT 后，或者门户状态对应其他设备。请用校园网线直连需要自动登录的电脑，再做「立即检测」。

当前适配：读取 `GET /tpl/whut/login_mobile.html` 和 `GET /tpl/whut/static/js/config.js`，检查现网页面和同源 API 基路径；之后用同一 Cookie 会话执行 `GET /api/csrf-token`、`GET /api/account/status?token=null`。登录为 `POST /api/account/login`（URL 编码表单），随后复查 `GET /api/account/status`。现网移动页使用 `switchip`，不会发送旧脚本的 `swtichip`。未纳入其他学校的 check、redial 和多线路逻辑。

## 日志、修复与卸载

数据目录为 `%LOCALAPPDATA%\WHUTKeepalive`。运行日志页面可搜索、复制和清理。诊断报告只含节点结果，不含密码、账号、Cookie、Token、MAC 或完整 IP。移动 EXE 后，在新位置打开程序，到「自动保活」保存并同步，即可修复计划任务路径。

移除时，先点击「暂停自动保活」，确认任务已移除，然后关闭程序并删除 EXE。「关于软件 → 恢复默认并清除凭据」会关闭保活、清除本地凭据与运行状态，保留日志。如需删除所有本地数据，卸载后自行删除上述目录。

后台命令（常规使用无需命令行）：`--check` 单次保活；`--status` 只读检测，结果在 `last-status.json`；`--diagnose` 生成脱敏报告；`--install-task` / `--uninstall-task` 安装 / 移除任务。命令反馈见该目录的 `last-command.json`；HTTP 提交同意只能在 GUI 中授予。

## 自行构建及来源

Windows x64 上安装 Go 1.24 或更新版本，运行 `go test ./...` 后，执行 `powershell -ExecutionPolicy Bypass -File .\scripts\build.ps1`。可用参数 `-GoExe <go.exe 完整路径>`。发布包包括 EXE、使用说明、测试记录及 SHA-256 校验表。源码另有压缩包，包含构建与测试脚本。
